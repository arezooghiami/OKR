# OKR — توضیح کامل محصول

> وضعیت: پیش‌نویس ۰.۱ برای تحلیل و تأیید. **جریان کار دقیق نسخه اول (جلسه هر واحد، نسخه‌بندی تعریف، مستندات، تب پایش) در [04-core-scenario.md](04-core-scenario.md) است و بر مفهوم «دور مرور سراسری» در این سند مقدم است.** · تاریخ: ۱۴۰۵ (۲۰۲۶-۱۰-۲۶) · نام کاری محصول: **OKR**

## ۱. محصول چیست؟

OKR یک **وب‌اپ مدیریت اهداف و نتایج کلیدی برای سازمان‌های بزرگ فارسی‌زبان** است که:

- روی **شبکه داخلی سازمان** نصب می‌شود و برای اجرا **به اینترنت نیاز ندارد**.
- با **هر ساختار سازمانی** (ساده، چندلایه، ماتریسی) سازگار است.
- **دسترسی‌ها، اصطلاحات، برند و گردش کار** آن را مدیر سیستم بدون برنامه‌نویسی تنظیم می‌کند.
- کار امروز اکسل‌محور سازمان‌ها را (جلسه‌های مرور، جمع‌بندی دستی، `#REF!` در گزارش‌ها) به **یک منبع حقیقت زنده، قابل ردیابی و قابل گزارش** تبدیل می‌کند.
- رابط کاربری آن فارسی/راست‌به‌چپ، با **تقویم جلالی** و اعداد فارسی است و **کیفیت UI اولویت اول** است.

## ۲. مسئله‌ای که حل می‌کند

برگرفته از بررسی فایل واقعی `OKR-1405-P2` سازمان نمونه (چرم مشهد: ۲۳ واحد، ~۱۴۰ Objective، ~۵۰۰ KR، ۶ دور مرور):

| درد امروز | آنچه محصول می‌دهد |
|---|---|
| هر واحد یک شیت جدا؛ جمع‌بندی دستی و شکننده (`#REF!`) | داشبورد زنده سازمان با drill-down تا ریز KR |
| داده کثیف: شماره‌گذاری تکراری، واحد نامشخص، مقادیر غلط | فیلدهای تایپ‌دار، اعتبارسنجی و ایمپورت کنترل‌شده |
| هیچ تاریخچه‌ای از تغییر عددها نیست | Audit log کامل (چه کسی، کی، از چه عددی به چه عددی) |
| تعهدات بین‌تیمی به‌صورت یک Objective ساختگی | تعهد/درخواست بین‌تیمی با وضعیت و پیگیری |
| هر کسی همه چیز را می‌بیند و تغییر می‌دهد (یا هیچ‌کس) | دسترسی دقیق و قابل تنظیم برای هر عمل و هر محدوده |
| ساختار سازمان وسط سال عوض می‌شود و گزارش‌ها به‌هم می‌ریزند | نسخه‌بندی ساختار؛ گزارش هر چرخه با ساختار همان زمان |
| ابزارهای خارجی: فارسی/جلالی ضعیف، ابر خارجی، سفارشی‌سازی کم | فارسی‌محور، on‑premise، سفارشی‌شدنی |

## ۳. مخاطبان و نقش‌ها

| نقش | هدف اصلی | نمونه کار روزانه |
|---|---|---|
| **مدیرعامل / مدیر ارشد** | دیدن وضعیت سازمان و همترازی | داشبورد سازمان، گزارش پایان دوره |
| **هماهنگ‌کننده OKR** (مرکزی) | اجرای چرخه و دورهای مرور | تعریف چرخه، پیگیری ثبت‌نشده‌ها، تأیید |
| **مدیر واحد** | مدیریت اهداف واحد خود | تعریف O/KR، ثبت مقادیر دور مرور |
| **عضو / مسئول KR** | به‌روزرسانی KR خود | ثبت مقدار و توضیح |
| **مدیر سیستم (IT)** | نصب، ورود کاربران، دسترسی‌ها | AD، ماتریس دسترسی، پشتیبان‌گیری |
| **ناظر** (فقط‌مشاهده) | شفافیت | مشاهده بدون ویرایش |

> نقش‌ها در محصول **قالب‌های آماده‌اند و قابل ویرایش**، نه ساختار ثابت (بخش دسترسی در PRD).

## ۴. مفاهیم اصلی (واژه‌نامه)

| مفهوم | معنی |
|---|---|
| **سازمان** | یک نصب = یک سازمان (single‑tenant) |
| **واحد (Unit)** | گره‌ای در درخت سازمان با **نوع** قابل تعریف (مثلاً معاونت، مدیریت، تیم) |
| **گروه مجازی** | مجموعه افراد خارج از درخت (کمیته، تیم پروژه) |
| **هدف کلان** | فهرست ثابت و قابل تنظیم اهداف راهبردی سازمان؛ هر KR می‌تواند به یکی برچسب بخورد |
| **چرخه (Cycle)** | بازه اجرای OKR (فصل، سال، بخش) با تقویم جلالی |
| **دور مرور (Review Round)** | جلسه/نقطه ثبت پیشرفت در چرخه (R1..Rn) |
| **Objective (هدف)** | هدف کیفی واحد در یک چرخه |
| **KR (نتیجه کلیدی)** | نتیجه قابل‌اندازه‌گیری یک Objective |
| **انواع KR** | عددی صعودی، عددی نزولی، مایلستون (۰–۱۰۰)، بله/خیر |
| ~~همترازی (Alignment)~~ | **بایگانی (۲۴ آبان ۱۴۰۵):** کنار گذاشته شد و کدش حذف شد. به جایش «اهداف کلان» می‌ماند: هر KR به یک هدف کلان سازمان برچسب می‌خورد |
| **تعهد بین‌تیمی** | درخواست/تعهد یک واحد از واحد دیگر با وضعیت و مهلت |
| **Snapshot ساختار** | نسخه ثابت درخت سازمان برای یک چرخه |

## ۵. قابلیت‌ها (دید سطح بالا)

1. **ساختار سازمانی**: درخت با عمق دلخواه، نوع واحد قابل تعریف، عضویت چندگانه (ماتریسی)، گروه مجازی، snapshot هر چرخه.
2. **چرخه و دورهای مرور**: تعریف چرخه، تعداد/تاریخ دورها، باز/بسته/قفل شدن، یادآوری.
3. **اهداف و KR**: ایجاد/ویرایش، انواع KR، وزن، خط مبنا و هدف، توضیح، مسئول، تیم‌های همکار، برچسب هدف کلان.
4. **ثبت پیشرفت**: جدول ویرایش درجا (شبیه اکسل) برای هر دور؛ مقدار، درصد محاسبه‌شده، یادداشت؛ گردش کار تأیید قابل تنظیم.
5. **همترازی و تعهدات**: درخت/گراف همترازی؛ تعهد بین‌تیمی.
6. **داشبوردها**: سازمان، واحد، فرد؛ مقایسه دورها؛ ریسک‌ها و عقب‌افتاده‌ها.
7. **گزارش‌ها**: PDF/Excel فارسی پایان دوره و پایان چرخه.
8. **ایمپورت/اکسپورت**: قالب‌های دانلودی نسخه‌دار، اعتبارسنجی، dry‑run.
9. **هویت و دسترسی**: حساب محلی + AD/LDAP؛ موتور دسترسی قابل تنظیم، شبیه‌ساز دسترسی.
10. **حسابرسی**: لاگ تغییرناپذیر برای داده و دسترسی.
11. **سفارشی‌سازی**: برند (لوگو، رنگ)، اصطلاحات، فهرست‌ها، گردش‌کار، قالب‌های گزارش.
12. **حالت دمو**: سازمان فرضی با داده نمونه برای معرفی بدون افشای داده واقعی.

## ۶. تجربه کاربری — اصول

- **کیفیت UI اولویت اول**: طراحی سیستماتیک (توکن‌های رنگ/فاصله/تایپوگرافی)، RTL از پایه، حالت‌های خالی/خطا/بارگذاری، دسترس‌پذیری (WCAG AA)، کار با کیبورد.
- **هر نقش یک صفحه خانه مرتبط**: مدیر ارشد داشبورد، مدیر واحد «کارهای دور مرور جاری»، عضو «KRهای من».
- **ثبت سریع**: ثبت یک مقدار حداکثر ۳ کلیک.
- **سرعت و حفظ جایگاه**: ذخیره خودکار پیش‌نویس، بدون از دست رفتن فیلترها.
- **اعداد قابل اعتماد**: هر درصد قابل کلیک تا فرمول و داده منبع.
- **فونت و آیکن محلی** (Vazirmatn)؛ هیچ منبع خارجی در زمان اجرا.

## ۷. چارچوب فنی (خلاصه)

| لایه | انتخاب |
|---|---|
| بک‌اند | Python 3.14، FastAPI، Poetry |
| دیتابیس | PostgreSQL، SQLAlchemy 2، **Alembic از روز اول** |
| ساختار کد | هم‌سبک پرتال `managment`: `routers / services / models / schemas / core`، رجیستری منو با گارد دسترسی |
| فرانت‌اند | **SPA**: React + TypeScript + Vite؛ بیلد استاتیک سرو‌شده از FastAPI (same‑origin، کوکی HttpOnly) |
| کارهای پس‌زمینه | بدون Redis در MVP (زمان‌بند سبک + صف مبتنی بر Postgres) |
| استقرار | Docker Compose + بسته آفلاین؛ بعداً Helm |
| مجوز | کلید آفلاین امضاشده (در صورت تصمیم تجاری) |

## ۹. شاخص‌های موفقیت پایلوت

- ورود کامل داده OKR-1405 چرم مشهد (۲۳ واحد) با **اعداد دقیقاً برابر اکسل**.
- ≥ ۹۰٪ مسئول‌های KR مقدار دور مرور را **در خود سامانه** ثبت کنند.
- جمع‌بندی گزارش دور مرور از «ساعت‌ها» به «کلیک» برسد.
- صفر خطای دسترسی/افشای داده در پایلوت.
- امتیاز رضایت کاربران کلیدی ≥ ۴ از ۵ (نظرسنجی کوتاه).
